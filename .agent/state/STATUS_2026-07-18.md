## What is demoed or incomplete

- The public Vercel UI does not run the engine. It replays the bundled 144-line `ui/public/demo-run.ndjson` fixture.
- The traffic is deterministic synthetic support-ticket data, not captured production OpenAI traffic. The baseline latency and cost values were generated to model realistic calls.
- The request-feed labels and starting daily cost are presentation values generated in the UI, not fields emitted by the engine.
- There is no web repo picker, upload flow, or server route that launches the engine. Audit-only public Git URL scanning is available in the CLI.
- `promptectomy serve` exposes validated persisted state and a local SSE stream. The UI consumes the same recorded envelope through `?live=`.
- There is no TUI. The product is a Typer CLI plus a web dashboard.
- The installed wheel contains its JSON schemas and can scan arbitrary local or public repositories. Full compilation still requires a Git checkout, a captured `.promptectomy/ledger.jsonl`, and the supported adapter/layout.
- The shim exists, but setup is not automated or documented as a copy-paste integration. It only patches synchronous, non-streaming `Responses.create`.
- Enabled hot-swap entries can return a valid local SDK Response even without a captured response envelope.
- Sampled shadow calls compare normalized original and compiled outputs, record the original call, and atomically disable the entry on drift. They do not automatically reopen synthesis or implement CI.
- `ui/fixtures/real-run.ndjson` contains four non-JSON command-output lines. The cleaned demo fixture is valid and is the deployed artifact.
