## What is demoed or incomplete

- The public Vercel UI does not run the engine. It replays the bundled 144-line `ui/public/demo-run.ndjson` fixture.
- The traffic is deterministic synthetic support-ticket data, not captured production OpenAI traffic. The baseline latency and cost values were generated to model realistic calls.
- The request-feed labels and starting daily cost are presentation values generated in the UI, not fields emitted by the engine.
- There is no web repo picker, upload flow, GitHub URL flow, or server route that launches the engine.
- There is no implemented local SSE bridge from CLI stdout to the dashboard. The UI can consume a live endpoint through `?live=`, but this repo does not provide that endpoint.
- There is no TUI. The product is a Typer CLI plus a web dashboard.
- The full `promptectomy run` path is not a generic installed tool yet. It assumes this repository layout, an existing `.promptectomy/ledger.jsonl`, bundled engine schemas, tagged callsites, and a Git repository.
- The shim exists, but setup is not automated or documented as a copy-paste integration. It only patches synchronous, non-streaming `Responses.create`.
- The synthetic registry has no stored OpenAI Response envelope, so its enabled hot-swap entries cannot currently return a real SDK Response through the shim.
- The 1% shadow path calls and records the original model in a background thread, but it does not compare outputs, disable a drifting replacement, reopen synthesis, or implement CI. The dashboard's final guard panel is the intended product design, not completed behavior.
- `ui/fixtures/real-run.ndjson` contains four non-JSON command-output lines. The cleaned demo fixture is valid and is the deployed artifact.
