## Accepted Phase 0 decisions

### Product and authority

- Product thesis: local-first repository-to-evidence-to-patch, not a generic autonomous code fixer.
- Any input may receive L0 inventory; deeper support is adapter- and evidence-scoped. Marketing must not imply that every codebase can receive verified optimization.
- Stable v1 target: Python and TypeScript/JavaScript, OpenAI Responses, sync/async/streaming/tools/structured-output/retry/error coverage.
- Inspect and Audit never write or execute the target. Draft writes only tool-owned storage. Without an accepted executor, Draft output is explicitly `unverified`. Apply is a separate explicit branch-based, digest-checked, previewed, recoverable action. Integrate remains distinct.
- Unsupported, insufficient-evidence, zero-work, failure, cancel, and interruption are typed visible outcomes. They cannot collapse into generic success.

### Architecture and security

- Target shape: Rust local control plane, SQLite event/projection state, content-addressed artifacts, Python/TypeScript adapters, explicit executor and AgentRuntime interfaces, and one local API consumed by CLI, Ratatui TUI, Tauri/React GUI, and static reports.
- Generated code and repository code never execute in the trusted core or clients. Verified Draft fails closed without an accepted isolation backend. There is no host fallback.
- Model transport credentials stay in a trusted connector and never enter offline repository/generated-code tool environments.
- Phase 1A uses a direct no-tool OpenAI Responses connector to an API-available Codex coding model. It does not use `codex exec` or Codex SDK threads for general Draft; missing capability fails closed without a patch.
- Git acquisition has explicit protocol, credential, configuration, helper, redirect, submodule, LFS/filter, hook, path, quota, and cleanup rules.
- Metadata-only evidence is the default. Source, trace content, and protected artifacts require a previewed egress manifest, destination, budget, consent, retention, and deletion behavior. Local-only mode forbids external model/source transmission.
- Tauri capabilities restrict client-to-native command access but are not treated as an untrusted-code sandbox.
- V1 receipts are SHA-256/JCS digest-bound local consistency evidence. They are not signed identity attestations.

### Contracts, UX, tests, and open source

- Contract v2 is specified around JSON Schema Draft 2020-12, typed UUIDv7/digest IDs, safe event envelopes, strict errors, explicit terminal states, append-only sequence semantics, artifacts, receipts, and cross-language compatibility.
- CLI, TUI, GUI, and reports are clients of one authority/state contract. Functional information architecture, consent, failure, review, agent-office, Apply, export, accessibility, and parity rules are specified.
- Every security invariant and threat family maps to named automated/manual test families. Synthetic golden repositories, hostile fixtures, privacy canaries, SLO candidates, benchmarks, and release blockers are defined.
- Apache-2.0 is the recommendation subject to legal and dependency-license review. DCO is the initial contribution recommendation. The name, namespaces, release claims, support window, signing, SBOM, provenance, and vulnerability process remain pre-release gates.

## Current implementation versus target

### Real in the hackathon implementation

- Python engine with capture ledger, Codex audit/synthesis, traffic split, worktree candidate generation, parent replay, scoring, registry, CLI, and local FastAPI/SSE bridge.

- Public replay at <https://promptectomy.vercel.app>.
- Narrow synchronous OpenAI Responses shim and the synthetic demonstrated verification path.

### Not implemented or not safe yet

- General non-mutating Inspect/Audit/Draft authority semantics.
- Tool-owned Draft snapshots and patches for arbitrary supported repositories.
- Out-of-process executor and hostile installed-wheel acceptance.
- Contract v2, durable SQLite state, protected content store, complete adapters, local control-plane API, Rust core, TUI, or Tauri GUI.
- Safe Apply/Integrate, bounded agent office, broad evaluation, CI/hosted runner, or production shadow deployment.
- Production security. The current generated Python path executes in-process, and the AST guard is only defense-in-depth.

The public Vercel site remains a recorded report renderer, not a hosted engine. The current source can audit more repositories than it can compile, and its general path must not be described as safe or production-ready.
